# UX/UI Deep Audit — 2026-07-25

Commander order (2026-07-25): "make a deep audit how more can we improve the UX/UI modern best
practices in every page and button of that system including the design." Run as a 12-agent
workflow: 1 inventory agent (33 surfaces mapped from server.py / warroom.py / cockpit_views.py),
5 surface auditors + 5 cross-cutting lenses (visual design system, interaction feedback,
IA/navigation, accessibility+responsive, microcopy/brand), 1 adversarial synthesis editor.
156 raw findings -> 20 merged as duplicates, 6 dropped as single-user-irrelevant noise,
130 folded into the 14 tickets below. Already-queued work (EU-538..EU-546, EU-532/534) was
excluded by contract so nothing here double-files it.

## Executive summary

- Strong today: the cockpit has good bones — a live board that updates every 2 seconds, a real design-token system with light/dark themes, and deep features (run history, forensics, usage, chat). Several parts already use the right patterns (the chat's append-only refresh, the models page's test-connection flow); the fixes mostly mean applying those good patterns everywhere.
- Biggest problem 1 — silent clicks: many action results (stop refused, start failed, QA finished, memory update failed) are written to places no page ever shows. You click, nothing visible happens, and errors disappear. Two P0 bugs sit here: per-project status messages are never rendered, and the live-log panel writes into a dead copy of the page so it freezes.
- Biggest problem 2 — the board fights you: the 2-second redraw deletes text you are typing into the security response box, resets panels you closed, and the live log never reconnects after a network blip. This must be fixed before the queued EU-543 log redesign, or that work inherits the same bug.
- Biggest problem 3 — some numbers lie: the budget gauge shows a green '100% remaining' when it simply could not read the data, the security form promises a Jira ticket that is never created, and the sync badge shows 'fresh' when one machine is days stale.
- Biggest problem 4 — light theme is half-broken: about ten pages hardcode dark colors instead of using the tokens, small grey text fails contrast in both themes, and the tokens themselves live in two hand-synced copies that already drifted apart.
- Biggest problem 5 — you cannot get around: five working pages (Report a problem, Meeting, Budget, Ship preview, Stand-up) have no link anywhere, tabs cannot be closed, and many actions dump you on a different project's board than the one you clicked in.
- Language still breaks the brand rules you set: 'the unit', 'drain', 'muster', 'Prebuild', 'DEV → MAIN' and raw error dumps survive on screen despite BRAND.md; one cheap sweep fixes ~25 findings.
- The plan: 14 tickets. Seven High tickets first (safe board refresh, visible action results, working Stop controls, click feedback, navigation, honest numbers, light-theme sweep), then Medium copy/consistency work. Of 156 raw findings: 130 kept inside the 14 tickets, 20 merged as duplicates, 6 dropped as noise for a single-user local tool.
